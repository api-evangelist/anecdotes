# Push custom evidence into Anecdotes

This is the flow for evidence Anecdotes cannot collect itself — an internal service, an air-gapped
system, or anything outside the 230+ plugin library. You become the collector.

## Prerequisites

Authenticate first (see `anecdotes-authenticate.md`). This flow needs the **Integrator** role or
higher.

## Steps

1. **Create the collection once.** Call `createEvidenceCollection` — `POST /evidence/v1/evidence/create`.
   This defines the evidence artifact that controls and requirements will map to. Do this once, not on
   every push. Keep the returned evidence id.

2. **Push data on your own cadence.** Call `uploadManualEvidence` — `POST /evidence/v1/evidence` — with
   each new collection run. The cadence is yours to choose; pick one that matches the control's
   expectation (daily, weekly, quarterly) so the analysis rules do not flag the evidence as stale.

3. **Attach large payloads instead of inlining them.** For large manual evidence use
   `attachEvidenceToCollection` — `POST /evidence/v1/evidence/{evidence_id}/attach`.

4. **Attach an IPE.** Call `attachEvidenceIpe` — `POST /evidence/v1/evidence/{evidence_instance_id}/ipe`
   — with either an `evidence_api_query` or an `ipe_file`. IPE (Information Produced by the Entity) is
   what an auditor uses to judge whether the evidence is trustworthy. You can attach it on the push or
   afterwards.

5. **Confirm the run landed.** Call `getEvidence` to read metadata, and `getCollectionMultiHistory` —
   `GET /evidence/v1/evidence/{evidence_id}/run_history` — to see the collection history and which
   instance is latest.

## Rules

- **Only API evidence can be written to.** A `400` with "The target evidence is not API
  (customer-pushed) evidence and cannot be written to" means you are pointing at plugin-collected
  evidence. Create your own collection instead.
- **Expect 422 on shape problems.** Validation errors come back as `{"detail": [{"loc": [...],
  "msg": "...", "type": "..."}]}` — one entry per failure. Read `loc` to find which field.
- **The IPE is labelled as external.** Anecdotes marks it "generated by an external system" in the app
  and in exports, because it cannot validate how you collected the data. This is expected, not an error.
- **Do not retry a failed push blindly.** There is no idempotency key. Call `getCollectionMultiHistory`
  and check whether your run already recorded before pushing again, or you will create duplicate
  instances.
